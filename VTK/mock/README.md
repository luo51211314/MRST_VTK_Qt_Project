# 压力场可视化系统（VTK）

## 项目概述

本项目是一个 **基于 VTK 的三维压力场可视化系统**，用于验证和展示：

* 三维压力场数据
* 裂缝几何（天然裂缝 / 人工裂缝）
* 井（Well）的空间位置与形态

当前系统支持 **两种压力场可视化方式**，并且已经支持 **直接从 Mock 数据接口生成完整场景**，不再依赖真实 CSV 文件即可运行。

> ⚠️ 本项目当前阶段的目标不是“物理精确模拟”，而是：
>
> * 验证 **数据 → 几何 → 渲染** 的完整链路
> * 为后续真实数据 / 接口接入提供稳定、可控的可视化基础

---

## 当前已实现功能（真实状态）

### ✅ 数据层

* 支持从 **CSV 文件**读取：

  * 网格信息
  * 压力场
  * 裂缝
  * 井
* 支持从 **MockData 接口**直接生成：

  * Grid / Cell / Fracture / Well
* 提供 `BuildSharedInputsFromMock(...)` 一次性构建渲染输入

### ✅ 可视化方式

* **堆叠层可视化（Stacked Layers）**

  * 沿 Z 方向分层显示压力场
* **实体立方体可视化（Solid Block）**

  * 半透明实体块 + 内部裂缝 / 井
* **仅裂缝 + 井视图**

  * 用于验证几何与井位置是否正确

### ✅ 几何对象

* 裂缝：四点构成的面片（区分 natural / artificial）
* 井：

  * 人工裂缝足够时：横向井（原逻辑）
  * 裂缝不足时：自动 fallback 为 **贯穿全层的竖井**
  * 保证 **任何数据情况下井一定可见**

## 重要设计说明（很关键）

### 关于“井一定能显示”

* `drawWells()` 不再依赖 **必须存在 3 条人工裂缝**
* 当人工裂缝不足时，自动 fallback：

  * 按井自身位置 `(x, y)`
  * 生成 **贯穿全 Z 层的竖井**
* 这保证：

  * Mock / 真实数据
  * 任意数量裂缝
  * 井永远不会“悄悄消失”

## 当前 Mock 数据说明（现状）

当前 `mock_data.cpp` 中：

* 压力场：规则网格，数值连续
* 裂缝：**1 条**
* 井：**1 口**

这已经足以验证：

* 数据管线
* 渲染流程
* 相机 / 遮挡 / 可见性问题

但 **数量过少，视觉效果比较“丑”**，这是已知且正常的。

# 下一步开发计划（重点）

## 🎯 目标

让 Mock 数据 **更像真实工程数据**，用于：

* 压力场空间变化验证
* 多裂缝 / 多井遮挡与布局测试
* 后续交互（Pick / Select / Layer Toggle）准备

---

## Step 1：Mock 随机化（推荐优先做）

### 1️⃣ 多井随机生成

* 参数示例：

  * `num_wells = 3 ~ 8`
* 规则：

  * `(x, y)` 随机分布在网格内部
  * `z` 可固定在中部
* 目的：

  * 验证多井重叠 / 远近 / 遮挡

### 2️⃣ 多裂缝随机生成

* 参数示例：

  * `num_fractures = 5 ~ 20`
* 可分两类：

  * `natural`（id < 100）
  * `artificial`（id ≥ 100）
* 每条裂缝：

  * 随机中心点
  * 固定或随机尺寸
  * 平面保持简单（先别追求复杂）

### 3️⃣ 压力场加入扰动

* 在规则压力场基础上加入：

  * 随机噪声
  * 或与井距离相关的衰减
* 目的：

  * 让等值变化更明显
  * 更接近真实“井影响区”

---

## Step 2：Mock 参数化（第二步）

把 Mock 变成 **可配置的“场景生成器”**：

```cpp
struct MockParams {
    int num_wells;
    int num_fractures;
    double pressure_noise;
    unsigned seed;
};
```

* 固定 seed：方便复现
* 改参数即可生成不同场景
